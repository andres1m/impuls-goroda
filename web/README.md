# Impuls Goroda Mini App

Run `npm ci` and `npm run dev` from `web/`. For local development, copy `public/config.example.json` to `public/config.json` and set `apiBaseUrl` to the gateway origin. Local HTTP is accepted only for localhost.

`npm run build` writes the static site to `web/dist`. The public HTTPS service in Compose serves that directory at `https://impulsgoroda.duckdns.org/` and provides `/config.json` with the same origin as the API. The local `public/config.json` is ignored by git; the deployment config contains only the public API address.

When `/config.json` contains `"prototypeMode": true`, the Mini App opens a clearly labeled synthetic route workspace. The MAX `startapp` payload selects a demo scenario; browser preview also accepts `?demo=vibe`. The three sample themes switch immediately. Rebuild offers a different local sample route within the selected theme and applies it only after review; it does not query the database. The workspace also includes manual start and finish, lunch, a conditional Pushkin Card mode, and local-only actions. Set `twoGisApiKey` in the runtime config to display the 2GIS map, geocode stops, and search nearby cafes. The gateway uses `TWO_GIS_API_KEY` to request route geometry. Without a key or when the map fails, the schedule remains available. Example route times and visits are not verified navigation, booking, or persistent server routes.

Lunch searches request the user's current location on each opening, then query real 2GIS cafes within the selected radius. Markers search falls back to Places search; an error never supplies invented cafes. Multiple lunch stops can be added, moved after a visit, or deleted independently. Choosing a cafe immediately inserts it into the local route and requests a walking path from the current location. Multiple lunch windows require schedule recalculation. Location used for the walking path stays in memory. Completed visits are marked green only after an explicit user action. Start and finish can be selected on the map. Pushkin Card settings never ask for a remaining balance.

With prototype mode disabled, the Mini App attempts to open the route selected for the signed-in MAX user. It reads the current context and owner route from the gateway; these handlers still need integration. If the bot has not selected a route, the API is unavailable, or MAX launch data is missing, it shows the corresponding state. A production map still needs a tile source and route geometry; the schedule remains readable without it.

`npm test` provides checks for runtime configuration, session exchange, route loading, and UI states. The latest prototype changes have not been tested; existing interaction expectations may need updating. The bot flow, owner route endpoints, and launch in MAX require separate end-to-end verification.
